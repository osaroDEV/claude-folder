Headings, Paragraphs & Text Structure

Text is the heart of most web pages. Today you'll learn how to organize it the way real websites do — with a clear, logical outline.

🎯 Learning Objectives
  • Use heading tags <h1> through <h6> correctly
  • Explain why heading order and hierarchy matter
  • Write body text using the <p> tag
  • Plan a page's structure like an outline before writing code

1Headings: h1 Through h6

HTML gives you six levels of headings, from biggest and most important (<h1>) to smallest (<h6>). Think of them exactly like the headings in a school essay or a book's table of contents: a big title, then section titles, then sub-section titles.

headings.html
<h1>Volcanoes</h1>
<h2>How Volcanoes Form</h2>
<h3>Tectonic Plates</h3>
<h2>Types of Volcanoes</h2>
<h3>Shield Volcanoes</h3>
<h3>Composite Volcanoes</h3>
🔒 headings.html

Volcanoes

How Volcanoes Form

Tectonic Plates

Types of Volcanoes

Shield Volcanoes

Composite Volcanoes

⚠️ The One-h1 Rule

Use exactly one <h1> per page — it should describe what the whole page is about, like a book's title. Never skip a level just to make text look smaller (like using <h4> because you think <h2> looks "too big"). Headings describe structure, not just size — save the look of things for CSS later.

2Paragraphs: The <p> Tag

Regular text content goes inside <p> (paragraph) tags. Browsers automatically add spacing above and below each paragraph, and — importantly — they collapse extra whitespace. That means pressing enter multiple times or adding extra spaces in your code won't create extra space on the page; only actual HTML tags control layout.

paragraphs.html
<p>Volcanoes are openings in the Earth's crust.</p>
<p>They   have      extra spaces
    and line breaks in this code —
    but the browser ignores them.</p>
🔒 paragraphs.html

Volcanoes are openings in the Earth's crust.

They have extra spaces and line breaks in this code — but the browser ignores them.

3Why Hierarchy Matters

A clear heading structure isn't just neat — it's functional. Search engines like Google scan your headings to understand what a page is about. People using screen readers (software that reads pages aloud for blind or low-vision users) can jump directly between headings, the same way you'd skim a table of contents. Skipping levels or using headings randomly makes pages confusing for both machines and humans.

4Plan Before You Code

Professional developers often sketch a page's outline in plain text before writing any tags. For example, a page about your favorite hobby might look like this:

  • H1: My Favorite Hobby — Skateboarding
  • H2: How I Got Started
  • H2: My Favorite Tricks
    • H3: The Ollie
    • H3: The Kickflip
  • H2: Why I Love It

Once your outline is clear, turning it into HTML is simple — you're just filling in tags around content you've already planned.

Heading
A title-style tag from <h1> (biggest) to <h6> (smallest)
Hierarchy

Paragraph
A block of regular text, wrapped in <p>
Whitespace collapsing

Screen reader

✅ Recap

Headings <h1>–<h6> create a page's outline — use exactly one <h1> and never skip levels for looks. Paragraphs <p> hold body text, and browsers collapse extra whitespace automatically. A clear hierarchy helps both search engines and screen reader users. Next lesson: formatting text with bold, italics, and special characters.

Lesson 4 of 16Week 2⏱ 60 minutes

Text Formatting, Entities & Comments

Learn how to emphasize important words, insert special characters, and leave yourself helpful notes inside your code.

🎯 Learning Objectives
  • Use <strong> and <em> to add semantic emphasis
  • Insert line breaks and horizontal rules appropriately
  • Use HTML entities to display special characters
  • Write comments that browsers ignore but humans can read

1Bold and Italic — the Right Way

HTML actually gives you two ways to make text bold, and two ways to make it italic. They look the same by default, but they mean different things:

  • <strong> — marks text as important (semantic meaning). Screen readers may say it with extra emphasis.
  • <b> — just makes text bold visually, with no special meaning.
  • <em> — marks text as emphasized, like you'd stress a word when speaking (semantic meaning).
  • <i> — just makes text italic visually, with no special meaning (often used for terms or titles).
💡 Which Should I Use?

Default to <strong> and <em> — they carry meaning for accessibility tools, not just looks. Save <b> and <i> for cases where you truly just want a visual style with no added importance, like a book title.

formatting.html
<p>Never share your <strong>password</strong> with anyone.</p>
<p>I <em>really</em> loved that movie.</p>
🔒 formatting.html

Never share your password with anyone.

I really loved that movie.

2Line Breaks & Horizontal Rules

Sometimes you need a line break within a paragraph (not a whole new paragraph). Use <br> for that. To draw a horizontal divider line between sections, use <hr>. Both are self-closing — they have no separate closing tag because they don't wrap any content.

address.html
<p>123 Maple Street<br>
Springfield, IL 62704</p>
<hr>
⚠️ Don't Overuse <br>

New learners often use several <br> tags in a row to create empty space. Don't — that's a job for CSS spacing later. Use <br> only when a genuine line break belongs inside one piece of content, like an address.

3HTML Entities: Typing Special Characters

Some characters have a special meaning in HTML — like < and >, which the browser normally reads as the start/end of a tag. To display these characters as plain text, you use an entity: a short code starting with & and ending with ;.

4Comments: Notes the Browser Ignores

You can leave notes for yourself (or teammates) directly in your code using comments. Browsers skip over anything inside <!-- --> completely — visitors never see it.

comments.html
<!-- TODO: add a photo here later -->
<p>This page is still under construction.</p>
<!-- End of intro section -->
📚 Key Vocabulary
Semantic
Carrying meaning, not just visual style
Entity
A code like &copy; used to display a special character
Self-closing tag
A tag with no separate closing pair, like <br> or <hr>
Comment
A note in code, wrapped in <!-- -->, invisible to visitors

✅ Recap

Use <strong> and <em> for meaningful emphasis, <br> and <hr> sparingly for breaks and dividers, entities for special characters, and comments to leave notes browsers won't display. Next lesson: organizing content into lists.
