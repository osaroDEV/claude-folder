Attributes Deep Dive & Accessibility Basics

You've been using attributes since Lesson 1. Today, let's understand them properly — and learn how to build pages that work for everyone.

🎯 Learning Objectives
  • Explain what an attribute is and how it modifies a tag
  • Use id and class correctly, and know the difference
  • Store custom information using data-* attributes
  • Apply core accessibility practices to your pages

1What Is an Attribute, Really?

An attribute is extra information added inside a tag's opening bracket, always in the form name="value". You've already used many: href, src, alt, type. Some attributes are global — they can be added to almost any tag — including id, class, title, and lang.

title-attr.html
<p title="This appears as a tooltip on hover">Hover over me.</p>

2id vs. class: When to Use Which

  • id — a unique identifier. Only one element on a page may use a given id. Perfect for jump-link targets or one specific element you'll reference.
  • class — a reusable label. Many elements can share the same class, and one element can have several classes separated by spaces. Perfect for styling groups of similar elements later with CSS.
id-class.html
<h1 id="page-title">My Page</h1>

<p class="highlight">Important note one.</p>
<p class="highlight">Important note two.</p>

3Custom Data with data-*

Sometimes you want to attach your own custom information to an element — information JavaScript can later read, but that isn't a "real" built-in attribute. HTML lets you invent your own, as long as they start with data-.

data-attr.html
<li data-difficulty="beginner">Introduction to Tags</li>

4Accessibility Basics: Building for Everyone

Accessibility means making sure your pages work for people with different abilities — including visitors who are blind, low-vision, motor-impaired, or using assistive technology like screen readers. The great news: you've already been learning accessibility this whole course, often without realizing it.

PracticeWhy it helps
Meaningful alt text on imagesLets screen reader users know what an image shows
Logical heading order (no skipped levels)Lets users navigate a page by its outline
Labels correctly linked to form fieldsLets users know what each field is for
Semantic elements (nav, main, footer...)Lets assistive tech announce page regions correctly
Descriptive link text (not "click here")Lets users understand a link out of context
💡 A Quick Intro to ARIA

For cases plain HTML can't describe, there's a toolkit called ARIA (Accessible Rich Internet Applications) — for example aria-label="Close menu" on an icon button with no visible text. You won't need it often as a beginner, since choosing the right semantic HTML tag solves most accessibility needs on its own — but it's good to know it exists.

Attribute
Extra info added inside a tag's opening bracket
Global attribute
An attribute usable on nearly any HTML tag
id
A unique identifier for one specific element
class
A reusable label shared by multiple elements
Accessibility
Designing so people of all abilities can use a page

🚀 Challenges

Three challenges, each a little tougher than the last. Challenge 1 is the must-do; Challenges 2 and 3 are where you level up.

Challenge 1CoreThe Accessibility Check

Go back through every page you've built so far and run an accessibility check: does every image have real alt text? Does every form label connect correctly? Is heading order logical with no skipped levels? Fix anything you find, then add one class attribute shared by at least two elements on the same page.

Challenge 2Level UpBook Club Shelf

Build bookclub.html with a list of five books (real or made-up). Then use attributes to organize it:

  • Give every <li> class="book", and give two of them a second class too: class="book must-read"
  • Give every book a data-genre attribute, like data-genre="mystery"
  • Give your #1 book id="favourite", and add a link at the top of the page that jumps to it (href="#favourite")
  • Add a title tooltip to two books with a one-line review

Finish with a comment answering: why can lots of books share class="book", but only one can have id="favourite"?

Challenge 3Boss LevelAccessibility Makeover

This bakery page works for some visitors — but not everyone. Copy it into bakery.html, then find and fix all 6 accessibility problems.

bakery.html
<div>
  <a href="index.html">Home</a>
  <a href="cakes.html">Cakes</a>
</div>

<h1>Welcome to Zainab's Bakery</h1>

<img src="images/cake.jpg">

<input type="text" id="order" name="order" placeholder="Your order">
<button>✖</button>

Next to each fix, write a short comment saying who it helps — for example, <!-- helps screen reader users know what the picture shows -->.

✅ Recap

Attributes add extra info to tags; id is unique, class is reusable, and data-* stores custom info. Accessibility means building pages that work for everyone — mostly achieved through the good habits you've already been practicing: real alt text, logical headings, linked labels, and semantic elements.
