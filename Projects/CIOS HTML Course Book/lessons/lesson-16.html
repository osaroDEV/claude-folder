Validating, Publishing & What's Next

The final lesson! Let's check your project is solid, put it online for others to see, and map out where your coding journey goes from here.

🎯 Learning Objectives
  • Explain why validating HTML matters
  • Recognize and fix the most common validation errors
  • Understand the basic steps to publish a page online
  • Identify what to learn next after HTML

1Why Validate Your HTML?

Browsers are surprisingly forgiving — they'll often still display a page even with mistakes in the code, silently guessing what you meant. That's convenient, but risky: your page might look fine in one browser and break in another. Validating means running your code through a checker that strictly confirms it follows the official HTML rules.

The W3C (the organization that maintains the HTML standard) provides a free validator online. You paste in your code or a page URL, and it lists every error and warning with an explanation.

2Common Errors & How to Fix Them

ErrorFix
"Element img is missing required attribute alt"Add a real alt attribute to every image
"Stray end tag"You have a closing tag with no matching opening tag — remove it or add the opening tag
"Unclosed element"You forgot a closing tag — find and add it
"Duplicate ID"Two elements share the same id — ids must be unique on a page
"Bad value for attribute"Usually a typo in an attribute value, like a misspelled type
💡 Validate Early and Often

Don't wait until a project is "finished" to validate — check it after each major section. Small, frequent fixes are far easier than untangling a page full of accumulated errors at the end.

3Publishing Your Page

A finished HTML file only needs a place to live online to become a real website. At a beginner level, there are simple, often free ways to do this — for example, free static hosting services (like GitHub Pages) let you upload your HTML files and instantly get a shareable web address. The general steps are always similar:

  1. Make sure all your file names and folder links are correct and lowercase
  2. Choose a hosting service and create an account (with a parent or teacher's help if needed)
  3. Upload your project folder (index.html, images, etc.)
  4. Visit the web address it gives you to see your page live!
⚠️ Ask Before You Publish

Before putting any page online publicly, check with a parent, guardian, or teacher — especially if it includes your photo or personal details. It's smart to avoid posting your full address, school name, or other identifying details on a public page.

4What's Next After HTML

You now have a real, transferable skill: you can read and write the language every website on Earth is built with. Here's where most learners go next:

🎨

CSS

Cascading Style Sheets — controls color, fonts, spacing, and layout. This is how you'll make your pages look genuinely beautiful.

⚡

JavaScript

Adds interactivity and logic — button clicks, animations, games, and dynamic behavior.

Everything you built in this course — the structure, the semantics, the accessibility habits — becomes the strong foundation that CSS and JavaScript build on top of.

🚀 Final Challenges

Three challenges, each a little tougher than the last. Challenge 1 is the must-do; Challenges 2 and 3 are where you level up.

Challenge 1CoreValidate & Publish

Run your finished profile page through an HTML validator and fix every error it reports. With a parent or teacher's help, publish your page online using a free hosting option. Share the link with a classmate, friend, or family member — you built a real website!

Challenge 2Level UpValidator Detective

Learn to read error messages by causing them on purpose. Make a copy of your page called broken-test.html and break it in three ways:

  • Delete one image's alt attribute
  • Give two different elements the same id
  • Delete one closing </section> tag

Paste the code into the W3C validator (validator.w3.org → "Validate by Direct Input"). Match each error message to a row in the Common Errors table above. Then delete broken-test.html — never publish the broken copy!

Challenge 3Boss LevelMy Coding Journey Page

Build journey.html — a portfolio page showing everything you made in this course:

  • An <h1> and a short intro paragraph
  • An ordered list of at least five pages you built (like signup.html, feedback.html, news.html) — each one a working link, plus one sentence about what it taught you
  • A table with two columns, Skill and How confident I feel (⭐ to ⭐⭐⭐), with at least five skills
  • A link back to your profile page — and a link to journey.html in your profile page's nav
  • A <footer> finishing the sentence: "Next, I want to learn CSS or JavaScript because…"

Copy your practice files into your my-profile-page folder so the links still work once it's online. Validate journey.html until it has zero errors, then publish it alongside your profile page.
