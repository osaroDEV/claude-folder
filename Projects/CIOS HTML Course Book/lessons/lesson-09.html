Forms Part 1: Collecting Input

Forms are how websites collect information from visitors — sign-ups, searches, quizzes, and more. Let's build your first one.

🎯 Learning Objectives
  • Create a form using the <form> element
  • Add text-based inputs using <input> and its type attribute
  • Correctly connect a <label> to its input
  • Use placeholder text appropriately

1The <form> Element

Everything a visitor fills in belongs inside a <form> element. For now, we'll focus on building forms visually — later courses cover sending form data to a server using the action and method attributes.

form-shell.html
<form>
  <!-- inputs go here -->
</form>

2Text Inputs & Input Types

The <input> tag is self-closing and creates most form fields. Its type attribute decides what kind of field it becomes — and modern browsers even validate some types automatically.

type valueCreates
textA single-line text field
emailA field that checks for a valid email pattern
passwordA field that hides typed characters
numberA field that only accepts numbers, often with up/down arrows
dateA field with a built-in date picker
inputs.html
<form>
  <label for="fullname">Full Name</label>
  <input type="text" id="fullname" name="fullname" placeholder="e.g. Amara Obi">
</form>
🔒 inputs.html

3Labels: Why for/id Matters

The <label> tag gives an input a visible, readable name — and connecting it correctly matters more than it looks. The label's for attribute must exactly match the input's id. When connected properly, clicking the label text also focuses (or checks) the input, and screen readers announce the label whenever the input is focused.

💡 Test It Yourself

Once you build a labeled input, click directly on the label text (not the box). If it's connected correctly, your cursor will jump into the input automatically. If nothing happens, double-check that for and id match exactly, including capitalization.

4Placeholder vs. Label — Don't Confuse Them

⚠️ A Common Mistake

New developers sometimes skip the <label> and rely only on placeholder text to explain a field. Don't — placeholder text disappears the moment someone starts typing, and screen readers may not announce it reliably. Placeholder text should only show an example of expected input (like "e.g. Amara Obi"), never replace a real label.

📚 Key Vocabulary
<form>
Container element for all input fields
<input>
A self-closing tag that creates a form field, styled by its type
<label>
Readable text describing a field, linked via for/id
placeholder
Faint example text shown inside an empty field
name attribute
Identifies the field's data when a form is submitted
🚀 Challenges

Three challenges, each a little tougher than the last. Challenge 1 is the must-do; Challenges 2 and 3 are where you level up.

Challenge 1CoreThe Sign-Up Form

Build signup.html with a <form> containing three properly labeled fields: full name (text), email (email), and age (number). Every <label> must be correctly linked to its <input> using matching for/id pairs. Test that clicking each label focuses its field.

Challenge 2Level UpLabel Detective

This form has 5 bugs hiding in it. Copy it into a new file called detective.html, find every bug, and fix it.

detective.html
<form>
  <label for="username">Username</label>
  <input type="text" id="user-name" name="username">

  <label for="Email">Email</label>
  <input type="email" id="email" name="email">

  <input type="password" id="password" placeholder="Password">

  <label for="birthday">Birthday</label>
  <input type="date" id="birthday">
</form>

Clues: two labels don't connect to their inputs, one field uses a placeholder pretending to be a label, and two fields are missing their name attribute. When you're done, click every label to prove it jumps into the right box.

Challenge 3Boss LevelLibrary Card Designer

Your school library wants an online library card form. Build library-card.html with these six fields — but this time you choose the best type for each one:

  • Full name
  • Email address
  • Date of birth
  • A secret 4-digit PIN that nobody looking over your shoulder should see
  • How many books you read last month
  • Your favourite author

Rules: every field needs a connected label and a name attribute. Add a placeholder example to at least two fields (as an example only — never instead of a label). Above each input, write an HTML comment explaining your choice, like <!-- date: gives a built-in date picker -->.

✅ Recap

Forms collect input inside <form>, using <input> fields whose type attribute determines behavior. Always pair a <label> with its input using matching for/id — never rely on placeholder text alone. Next lesson: checkboxes, dropdowns, and buttons.
