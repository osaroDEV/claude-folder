Headings, Paragraphs & Text Structure

Text is the heart of most web pages. Today you'll learn how to organize it the way real websites do — with a clear, logical outline.

🎯 Learning Objectives
  • Use heading tags <h1> through <h6> correctly
  • Explain why heading order and hierarchy matter
  • Write body text using the <p> tag
  • Plan a page's structure like an outline before writing code

1Headings: h1 Through h6

HTML gives you six levels of headings, from biggest and most important (<h1>) to smallest (<h6>). Think of them exactly like the headings in a school essay or a book's table of contents: a big title, then section titles, then sub-section titles.

headings.html
<h1>Volcanoes</h1>
<h2>How Volcanoes Form</h2>
<h3>Tectonic Plates</h3>
<h2>Types of Volcanoes</h2>
<h3>Shield Volcanoes</h3>
<h3>Composite Volcanoes</h3>
🔒 headings.html

Volcanoes

How Volcanoes Form

Tectonic Plates

Types of Volcanoes

Shield Volcanoes

Composite Volcanoes

⚠️ The One-h1 Rule

Use exactly one <h1> per page — it should describe what the whole page is about, like a book's title. Never skip a level just to make text look smaller (like using <h4> because you think <h2> looks "too big"). Headings describe structure, not just size — save the look of things for CSS later.

2Paragraphs: The <p> Tag

Regular text content goes inside <p> (paragraph) tags. Browsers automatically add spacing above and below each paragraph, and — importantly — they collapse extra whitespace. That means pressing enter multiple times or adding extra spaces in your code won't create extra space on the page; only actual HTML tags control layout.

paragraphs.html
<p>Volcanoes are openings in the Earth's crust.</p>
<p>They   have      extra spaces
    and line breaks in this code —
    but the browser ignores them.</p>
🔒 paragraphs.html

Volcanoes are openings in the Earth's crust.

They have extra spaces and line breaks in this code — but the browser ignores them.

3Why Hierarchy Matters

A clear heading structure isn't just neat — it's functional. Search engines like Google scan your headings to understand what a page is about. People using screen readers (software that reads pages aloud for blind or low-vision users) can jump directly between headings, the same way you'd skim a table of contents. Skipping levels or using headings randomly makes pages confusing for both machines and humans.

4Plan Before You Code

Professional developers often sketch a page's outline in plain text before writing any tags. For example, a page about your favorite hobby might look like this:

  • H1: My Favorite Hobby — Skateboarding
  • H2: How I Got Started
  • H2: My Favorite Tricks
    • H3: The Ollie
    • H3: The Kickflip
  • H2: Why I Love It

Once your outline is clear, turning it into HTML is simple — you're just filling in tags around content you've already planned.

📚 Key Vocabulary
Heading
A title-style tag from <h1> (biggest) to <h6> (smallest)
Hierarchy
The order of importance shown by heading levels
Paragraph
A block of regular text, wrapped in <p>
Whitespace collapsing
Browsers ignore extra spaces/line breaks in your code
Screen reader
Software that reads a web page aloud for accessibility
🚀 Challenge

Create hobby.html with a full page structure (doctype, head with title, body). Inside the body, write a page about a hobby or interest of yours using: one <h1>, at least two <h2> sections, one <h3> inside a section, and at least three <p> paragraphs total.

✅ Recap

Headings <h1>–<h6> create a page's outline — use exactly one <h1> and never skip levels for looks. Paragraphs <p> hold body text, and browsers collapse extra whitespace automatically. A clear hierarchy helps both search engines and screen reader users. Next lesson: formatting text with bold, italics, and special characters.
