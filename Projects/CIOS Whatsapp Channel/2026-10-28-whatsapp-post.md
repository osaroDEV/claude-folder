- **Best time for Post 1:** 8:00 GMT exactly on the day you post it — ideally within 10 minutes of session three (or four, if you're posting Thursday) actually starting, so the "the kettle's on, mid-week" framing is literally true. - **The three [Child's first name] slots are the whole post. Rotate them — pick three DIFFERENT real kids from Monday's named three.** This is the single most important edit of the day. If the Tuesday post named [kid A, 8–11], [kid B, intermediate], [kid C, teen], this post should name three different kids — ideally one from each track again, so the channel reads as "many children in a programme." **Get a one-line permission from each parent before posting** ("hey, can we mention [name] built [X] this week on the channel? first name only, no photo"), and replace the placeholders with real names and real builds. **Never invent a kid or a build.** If permission is tricky, fall back to "a child in the [track] track built…" — but keep the specific build details, those are what make the post work.

"A webpage with four colour themes" is more convincing than "a webpage with colours," even if the project itself is modest. The texture is the whole point.
- **Functions is today's real teaching beat.** The post names functions because Day 3 of a beginners' coding week is almost always where functions land (after Mon = write code, Tue = loops). But if your actual Wed/Thu curriculum is something different (variables, conditionals, data), rewrite the one teaching line to match. The parent-facing hook *"what did you make that you didn't have to make twice?"* only works for functions — if you teach a different beat, swap the question to something that matches: for conditionals, *"what did you build that makes a decision?"*; for variables, *"what in your project changes while it's running?"*.
