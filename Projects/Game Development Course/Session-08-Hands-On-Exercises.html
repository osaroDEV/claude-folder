Hands-On Exercises — The Game Loop

Work through these in order. Every exercise is a small change to the same skeleton you built in class: update(), draw(), loop(). Type the code yourself — do not copy and paste. Press Run to see your change immediately.

What you are practising

  • Making a loop run forever with requestAnimationFrame
  • Keeping thinking (update) and painting (draw) in separate functions
  • Clearing the canvas so motion looks clean instead of smeared
  • Diagnosing the two classic loop bugs on your own

1

The Speed Dial

⭐ Warm-up5 minObserve
Goal: prove to yourself that one number controls how fast the world moves, and that speed is measured in pixels per frame.
  1. Press Run first and just watch. The square moves right and wraps around.
  2. Change speed: 3 to speed: 8. Run again.
  3. Change it to speed: 1. Run again.
  4. Now try speed: 0.5 — a decimal is allowed! Does it still move?
  5. Finally try speed: -3. Which way does it go? Can you explain why before you run it?

Write your answer: the loop runs about 60 times a second. If speed is 3, how many pixels does the square travel in one second? Work it out on paper.

Hint
speed is added to player.x once per frame, not once per second. 60 frames × 3 pixels = ?
exercise-1.html
Edit the code above, then press Run
Solution & teacher notes

Maths answer: 3 pixels × 60 frames = 180 pixels per second. The canvas is 360 wide, so the square crosses it in about 2 seconds.

speed: 0.5 — yes, it still moves, just very slowly (30 px/sec). Position doesn't have to be a whole number; the canvas handles decimals fine.

speed: -3 — it moves left, because adding a negative number subtracts. The extra if (player.x < -player.size) line catches it and wraps it to the right side.

Watch for: a student who says "speed 3 means 3 pixels per second." Push them to notice the loop runs 60 times a second — this is the single most useful mental model for the rest of the course.

Doctor, My Loop Is Frozen

⭐ Debug5 minFix the bug
Goal: recognise the "runs once and stops" bug on sight. This code is broken on purpose.
  1. Press Run. The square appears but never moves.
  2. Before touching anything, write down what you think is missing.
  3. Find the bug and fix it with one line.
  4. Run again to confirm it moves.
🔍 Detective question
Did the square get drawn at all? If yes, then update() and draw() definitely ran at least once. So the problem isn't that the code is wrong — it's that nothing is asking for the next frame.
Hint
Compare loop() in this file with the one from class. Something is missing inside the function. Remember: the loop has to ask the browser to call it again.
exercise-2-broken.html
One missing line
Solution & teacher notes
function loop() {
  update();
  draw();
  requestAnimationFrame(loop);   // <-- THE FIX
}

The idea to land: requestAnimationFrame books exactly one future frame — it is not a "repeat forever" command. The loop only continues because each frame books the next one. The single call at the bottom of the file starts the chain; the call inside the function keeps the chain alive.

Good analogy for the student: it's like a relay race. Each runner must hand the baton to the next runner. Remove one hand-off and the race stops there.

3

The Snake Trail

⭐ Debug7 minFix the bug
Goal: see the #1 beginner animation bug with your own eyes, then fix it — and then use it on purpose.
  1. Press Run. The square leaves a long smear behind it.
  2. Explain out loud why: what is the canvas actually doing on each frame?
  3. Fix it by adding one line at the top of draw().
  4. Now the fun part. Instead of clearRect, try painting a see-through black rectangle over the whole canvas each frame: 
    ctx.fillStyle = "rgba(11, 14, 36, 0.08)";
ctx.fillRect(0, 0, W, H);
    Run it. What effect do you get? Try changing 0.08 to 0.3 and to 0.02.
Hint
The canvas never erases itself. Whatever you painted last frame is still sitting there. Your draw() function must wipe the old picture before painting the new one — ctx.clearRect(0, 0, W, H).
exercise-3-smear.html
Add one line inside draw()
Solution & teacher notes
function draw() {
  ctx.clearRect(0, 0, W, H);   // <-- THE FIX: wipe first
  ...
}

Step 4 result: a fading motion trail / comet tail. A translucent rectangle only partly hides the old frames, so recent positions fade out gradually. Higher alpha (0.3) = short tail; lower alpha (0.02) = long ghostly tail.

Why this matters: it reframes "the bug" as "a technique." The student learns that clearing isn't magic — it's just painting over the top, and controlling how much you paint over gives you a real visual effect used in actual games.

Common mistake: putting clearRect at the bottom of draw() — the canvas then looks empty (they wipe the thing they just drew). Great teaching moment about order of operations.

4

Go Diagonal

⭐⭐ Build8 minWrite code
Goal: move on both axes and wrap on both. Y works exactly like X — nothing new to learn, just applied twice.
  1. Give the player a second speed variable, speedY, and rename the first one speedX.
  2. In update(), add speedY to player.y.
  3. Add the vertical wrap: if the square goes past the bottom, put it back above the top.
  4. Try speedX: 2, speedY: 1 then speedX: 1, speedY: 4. Notice the angle changes.
  5. Think: what pair of values makes it move at a perfect 45°?
💡 Remember your canvas axes
On a canvas, y gets bigger as you go DOWN, not up. So speedY: 2 moves downward.
Hint
Your vertical wrap is a mirror image of the horizontal one:
if (player.y > H) { player.y = -player.size; }
exercise-4-diagonal.html
Three TODOs
Solution & teacher notes
let player = { x: 0, y: 0, size: 34, speedX: 2, speedY: 1.4 };

function update() {
  player.x += player.speedX;
  player.y += player.speedY;

  if (player.x > W) { player.x = -player.size; }
  if (player.y > H) { player.y = -player.size; }
}

45° answer: when speedX and speedY are equal (e.g. both 2). Ask them to test their prediction rather than taking your word for it.

This is the seed of "velocity" — Session 9 renames speedX/speedY to vx/vy and makes the object bounce instead of wrap. Flag that connection out loud so Session 9 feels like a continuation, not a new topic.

5

Two Things at Once

⭐⭐ Build10 minWrite code
Goal: prove the loop can drive any number of objects. One update(), one draw() — two independent things moving at different speeds.
  1. Create a second object called ball with its own x, y, r (radius) and speed.
  2. In update(), move the ball too — give it a different speed from the square.
  3. In draw(), draw the ball as a circle after the square.
  4. Make the ball travel right to left (negative speed) and wrap around the correct edge.
  5. Experiment: swap the order of the two drawing sections. Which shape ends up on top? Why?
💡 Drawing a circle
ctx.beginPath();
ctx.arc(x, y, radius, 0, Math.PI * 2);
ctx.fill();
Always start with beginPath(), or your circles join up into one weird shape.
Hint
Don't create new functions. Just add more lines inside the existing update() and draw(). Each object needs its own variables so they can move independently.
exercise-5-two-objects.html
Three TODOs
Solution & teacher notes
let ball = { x: 360, y: 150, r: 18, speed: -3.2 };

function update() {
  player.x += player.speed;
  if (player.x > W) { player.x = -player.size; }

  ball.x += ball.speed;                        // negative = leftwards
  if (ball.x + ball.r < 0) { ball.x = W + ball.r; }
}

function draw() {
  ctx.clearRect(0, 0, W, H);

  ctx.fillStyle = "#34d399";
  ctx.fillRect(player.x, player.y, player.size, player.size);

  ctx.fillStyle = "#fbbf24";
  ctx.beginPath();
  ctx.arc(ball.x, ball.y, ball.r, 0, Math.PI * 2);
  ctx.fill();
}

Step 5 answer: whatever is drawn last appears on top. The canvas is like painting — later strokes cover earlier ones. This is "draw order," and it's why in a real game you draw the background first and the player near the end.

Common mistake: re-using the same variable name for both objects, or forgetting beginPath(). If their circle grows a strange tail connecting to the square, that's the missing beginPath().

Tidy the Messy Code

⭐⭐ Refactor8 minThink like a pro
Goal: this code works, but it breaks the rule from class: the referee is doing the camera's job. Reorganise it without changing what the user sees.

Remember the rule: update() changes the world and draws nothing. draw() paints the world and decides nothing.

  1. Run it first — confirm it works as-is. (Working code can still be bad code!)
  2. Find every drawing instruction that is sitting inside update().
  3. Move them into draw(), in the right order.
  4. Find any decision/logic that is sitting inside draw(), and move it into update().
  5. Run again. It must look exactly the same. If it changed, you moved something in the wrong order.
🧠 Why bother, if it already works?
Because in three weeks this file will be 300 lines long. When the ball moves wrong, you want to look in one place. Mixing the two jobs is how beginners end up with games they can no longer fix.
Hint
Anything starting with ctx. is drawing and belongs in draw(). Anything that changes a value like .x, .y or score, or any if that makes a rule decision, is logic and belongs in update().
exercise-6-messy.html
Same behaviour, cleaner code
Solution & teacher notes
function update() {          // ONLY logic
  box.x += box.speed;

  if (box.x > W) {
    box.x = -box.size;
    laps = laps + 1;
  }
}

function draw() {            // ONLY painting
  ctx.clearRect(0, 0, W, H);

  ctx.fillStyle = "#9a6bff";
  ctx.fillRect(box.x, box.y, box.size, box.size);

  ctx.fillStyle = "#e9ecff";
  ctx.font = "16px sans-serif";
  ctx.fillText("Laps: " + laps, 12, 26);
}

The order trap (step 5): clearRect must be the first line of draw(). If a student leaves it after the fillRect, the canvas goes blank. Let them hit it — it's a 10-second fix and a permanent lesson.

Mark them right if: no ctx. anywhere in update(), no if-decision or position change anywhere in draw(), and the lap counter still increases.

The Breathing Square

⭐⭐⭐ Stretch10 minThink
Goal: realise that a game loop can animate anything that is a number — not just position. Here you animate size, and reverse direction at the limits.
  1. Make the square grow by grow pixels every frame.
  2. When size passes 90, reverse the direction (make grow negative).
  3. When size drops below 20, reverse it again.
  4. Keep the square centred while it breathes — that's the tricky part.
  5. Extra: animate the colour too. Rotate through an array of colours every time it reverses.
💡 The reversing trick
To flip a direction, multiply by −1: grow = grow * -1; — this exact trick is what makes balls bounce in Session 9.
💡 Keeping it centred
A rectangle is drawn from its top-left corner. So to keep the middle in the same place, the top-left has to move as the size changes:
const x = W/2 - size/2;  const y = H/2 - size/2;
Hint
In update(): box.size += box.grow; then two if statements that flip box.grow. In draw(): work out the top-left corner from the current size, then fillRect.
exercise-7-breathe.html
Four TODOs
Solution & teacher notes
function update() {
  box.size += box.grow;

  if (box.size > 90) { box.grow = box.grow * -1; }
  if (box.size < 20) { box.grow = box.grow * -1; }
}

function draw() {
  ctx.clearRect(0, 0, W, H);

  const x = W / 2 - box.size / 2;
  const y = H / 2 - box.size / 2;

  ctx.fillStyle = "#34d399";
  ctx.fillRect(x, y, box.size, box.size);
}

Extra (colour rotation):

const colours = ["#34d399", "#6c8cff", "#fbbf24", "#fb7185"];
let ci = 0;
// inside each reverse:  ci = (ci + 1) % colours.length;
// in draw():            ctx.fillStyle = colours[ci];

That % wrap-around is straight from Session 7 — point it out, it's a nice "you already know this" moment.

Trap to watch for: writing if (box.size > 90) { box.grow = -0.8; } with a hard-coded number instead of * -1. It works here, but breaks the moment the speed changes. Ask: "what if I later set grow to 2?"

Boss Challenge — Busy Road

⭐⭐⭐ Boss15–20 minCombines S5–S8
Goal: build a whole mini-scene from the skeleton, using everything from Month 1 — objects, arrays (S7), a for loop (S7), an if (S6), functions (S5) and the game loop (S8).

The brief

Four cars drive across four lanes of a road. Each car has its own lane, own colour and own speed. When a car leaves one side of the screen it reappears on the other. A counter in the corner shows how many frames have been drawn.

Requirements checklist

  • ☐ The cars are stored in one array, not four separate variables
  • ☐ update() uses a for loop to move every car
  • ☐ draw() uses a for loop to draw every car
  • ☐ Each car has a different speed — at least one drives the opposite way
  • ☐ Cars wrap correctly on both edges
  • ☐ A frame counter is displayed with ctx.fillText
  • ☐ No ctx. anywhere inside update()
  • ☐ Adding a 5th car takes one line of code
🏆 The real test
When you're done, add a fifth car. If you had to change update() or draw() to do it, your loop isn't doing its job — go back and fix that. Good code lets you add content without touching logic.
Hint 1 — how to shape the array
let cars = [
  { x: 0,   y: 20,  w: 60, h: 26, speed: 2,    colour: "#34d399" },
  { x: 120, y: 70,  w: 60, h: 26, speed: 3.5,  colour: "#6c8cff" },
  ...
];
Every car is the same shape of object, so one piece of code can handle all of them.
Hint 2 — looping over the array
for (let i = 0; i < cars.length; i++) {
  const car = cars[i];
  car.x += car.speed;
}
Pulling cars[i] into a variable called car makes the rest of the lines much easier to read.
Hint 3 — wrapping in both directions
if (car.speed > 0 && car.x > W)      { car.x = -car.w; }
if (car.speed < 0 && car.x + car.w < 0) { car.x = W; }

Full solution & teacher notes
let frames = 0;

let cars = [
  { x: 0,   y: 40,  w: 64, h: 26, speed:  2.0, colour: "#34d399" },
  { x: 140, y: 90,  w: 64, h: 26, speed:  3.6, colour: "#6c8cff" },
  { x: 300, y: 140, w: 64, h: 26, speed: -2.6, colour: "#fbbf24" },
  { x: 60,  y: 190, w: 64, h: 26, speed:  1.2, colour: "#fb7185" }
];

function update() {
  frames = frames + 1;

  for (let i = 0; i < cars.length; i++) {
    const car = cars[i];
    car.x += car.speed;

    if (car.speed > 0 && car.x > W)          { car.x = -car.w; }
    if (car.speed < 0 && car.x + car.w < 0)  { car.x = W; }
  }
}

function draw() {
  ctx.clearRect(0, 0, W, H);

  for (let i = 0; i < cars.length; i++) {
    const car = cars[i];
    ctx.fillStyle = car.colour;
    ctx.fillRect(car.x, car.y, car.w, car.h);
  }

  ctx.fillStyle = "#e9ecff";
  ctx.font = "14px sans-serif";
  ctx.fillText("Frames: " + frames, 12, 22);
}

Teacher notes

  • The whole point is that update() and draw() never mention "car 1" or "car 3". They just say "for every car…". Adding a fifth car is one new line in the array. Make the student actually do it and watch it appear — that moment is the lesson.
  • Frame counter reality check: after about 10 seconds the counter should read roughly 600. Ask them to time it. It's a lovely concrete confirmation of "60 frames per second."
  • Likely stumbles: forgetting cars.length and hard-coding i < 4; declaring the array after the functions that use it (works with let at top level, but teach the habit of declaring state first); putting the frame counter inside update() where ctx doesn't belong.
  • If they finish early: ask for lane divider lines drawn under the cars, or make each car's colour come from a separate colours array using colours[i % colours.length].

🚀 If you finish everything — extension tasks

These are optional. Pick whichever sounds most fun.

  1. Pause button. Add let running = true; and make a click on the canvas flip it. When running is false, skip update() but still draw(). Notice how the picture stays but the world freezes — that's the update/draw split earning its keep.
  2. Speed ramp. Make the square get slightly faster every lap. How many laps before it moves so fast it "teleports"? Why does that happen?
  3. FPS display. Count frames for one second (using Date.now()) and print the real FPS on screen. Is it really 60 on your machine?
  4. Comet. Combine exercise 3's fading trail with exercise 4's diagonal movement to make a comet that streaks across the canvas.
