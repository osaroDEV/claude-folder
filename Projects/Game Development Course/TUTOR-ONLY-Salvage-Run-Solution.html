index.html — the complete file, and it doesn't change again

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <title>Salvage Run — Station Kepler</title>
  <link rel="stylesheet" href="style.css" />
</head>
<body>

  <h1>SALVAGE RUN</h1>
  <p class="tagline">Station Kepler · Sector Salvage Authority</p>

  <canvas id="game" width="720" height="480"></canvas>

  <p class="controls">
    <b>Arrow keys</b> fly the tug · <b>Click</b> an orange unstable rock to vaporise it ·
    <b>P</b> pause · <b>R</b> restart
  </p>

  <script src="game.js"></script>
</body>
</html>

Why it's written this way

  • Canvas size is in the HTML, not the CSS. The single most important detail in this stage. CSS width/height stretches the canvas like a scaled photo — the drawing surface stays 300×150 and every coordinate goes subtly wrong. If their clicks and shapes are mysteriously offset later, check this first.
  • The script tag is at the end of the body. If it's in the head, getElementById runs before the canvas exists and returns null. The error message they'd see — "Cannot read properties of null" — is worth showing them on purpose once.
  • The controls line is real UI, not decoration. Marking criterion: can a stranger play it without asking a question?

The stylesheet

Any reasonable CSS passes. The reference version uses text-align: center on the body to centre the canvas (a canvas is an inline element, so this works and is the simplest thing that does). margin: 0 auto with display: block is equally correct — accept either, and ask which they chose and why.

⚠️ Expect this one
Symptom: the console message never appears. Cause: nine times in ten it's the filename — game.JS, Game.js, or the file saved outside the folder. What to ask instead: "Open the Network tab and reload. Is the browser even asking for that file, and what does it say back?"

Settings, the core, and text on the canvas

Sessions 2, 4, 5~25 min
// ---- 1. THE CANVAS ----
const canvas = document.getElementById("game");
const ctx = canvas.getContext("2d");
const W = canvas.width;      // 720 — used constantly, so store it once
const H = canvas.height;     // 480

// ---- 2. SETTINGS (const — decided once, never changes) ----
const FPS = 60;
const ROUND_SECONDS = 60;
const TUG_W = 46, TUG_H = 26, TUG_SPEED = 5;
const POD_SIZE = 18, PODS_PER_WAVE = 8, POD_SAFE_GAP = 90, HUD_H = 40;
const START_ROCKS = 3, ROCK_MIN_R = 12, ROCK_MAX_R = 26;
const ROCK_MIN_SPEED = 0.8, ROCK_MAX_SPEED = 2.5;
const UNSTABLE_EVERY = 5;
const CORE_R = 44, START_SHIELD = 10;
const DAMAGE_NORMAL = 1, DAMAGE_UNSTABLE = 3;
const SCORE_POD = 10, SCORE_WAVE = 50, SCORE_VAPORISE = 25, SCORE_MISCLICK = 5;

const COL_TUG = "#34d399", COL_POD = "#6c8cff", COL_ROCK = "#a3aad6";
const COL_UNSTABLE = "#fbbf24", COL_CORE = "#9a6bff";
const COL_TEXT = "#e9ecff", COL_BAD = "#fb7185";

// ---- 3. STATE (let — these change as we play) ----
let score = 0;
let wave = 1;
let paused = false;
let gameOver = false;

const core = { x: W / 2, y: H / 2, r: CORE_R, shield: START_SHIELD };

// ---- 5. DRAWING HELPERS ----
function drawRect(r, colour) {
  ctx.fillStyle = colour;
  ctx.fillRect(r.x, r.y, r.w, r.h);
}

function drawCircle(c, colour) {
  ctx.fillStyle = colour;
  ctx.beginPath();
  ctx.arc(c.x, c.y, c.r, 0, Math.PI * 2);
  ctx.fill();
}

// ---- first paint, just to prove it works ----
drawCircle(core, COL_CORE);
ctx.fillStyle = COL_TEXT;
ctx.font = "17px system-ui";
ctx.fillText("Score: " + score + "    Wave: " + wave + "    Shield: " + core.shield, 14, 28);

Why it's written this way

  • W and H stored once. They get used forty times. Typing canvas.width everywhere is noise, and this is their first taste of "name the thing you keep repeating".
  • The settings block is the graded part. A student who scatters 5 and 10 and 44 through the file will still have a working game — and will be unable to tune it. Self-test #10 is designed to expose exactly that, so don't fix it for them now; let the self-test catch it.
  • core is const but core.shield changes. This surprises people and it's a genuinely valuable five-minute conversation: const locks which object the name points at, not what's inside it. Ask them to predict whether core.shield -= 1 will error, then try it.
  • drawRect and drawCircle exist from the very start. Without them, beginPath/arc/fill gets copy-pasted a dozen times. Insisting on the helpers now is what makes Stage 8's clean-up pass small instead of brutal.
🎯 The HUD is one string, built from variables
Watch for five separate fillText calls with hardcoded labels at guessed x positions. It works, it looks fine, and it's the wrong habit. One joined string, one draw call.
⚠️ Expect this one
Symptom: "nothing draws". Cause: forgot getContext("2d"), or the script is in the head. What to ask instead: "Print ctx to the console. What is it?" — null or undefined answers the question for them.

The engine: update, draw, loop

Sessions 8, 5, 6The keystone stage
let frames = 0;          // counts only UNPAUSED frames — that IS the clock
let endReason = "";

function timeLeft() {
  return Math.max(0, ROUND_SECONDS - Math.floor(frames / FPS));
}

document.addEventListener("keydown", function (e) {
  // e.repeat is true when the key is auto-repeating from being held down.
  // Without this, holding P flickers pause on and off 30 times a second.
  if (e.repeat === false) {
    if (e.key === "p" || e.key === "P") { paused = !paused; }
    if (e.key === "r" || e.key === "R") { resetGame(); }
  }
});

function update() {
  if (paused === true || gameOver === true) { return; }   // <-- THE GUARD
  frames++;
}

function draw() {
  ctx.clearRect(0, 0, W, H);        // ALWAYS the first line
  drawCircle(core, COL_CORE);
  drawHud();
  if (paused === true)   { drawBanner("PAUSED", "Press P to carry on"); }
  if (gameOver === true) { drawBanner(endReason, "Final score " + score + " — press R to fly again"); }
}

function loop() {
  update();
  draw();
  requestAnimationFrame(loop);
}

resetGame();
requestAnimationFrame(loop);

Why it's written this way

  • The guard is the lesson. if (paused || gameOver) return; as the first line of update() replaces wrapping the entire function in a giant if. It reads better, it nests less, and it's a pattern they'll use forever. If they wrote the giant if, accept it — then show them this and ask which they'd rather read in a month.
  • The frame counter is the clock. Because frames++ sits below the guard, pausing genuinely stops time. No separate timer variable, no setInterval fighting the game loop. One counter does the countdown, the 5-second unstable trigger, and the pause behaviour all at once.
  • Math.floor(frames / FPS). Without the floor they get Time: 41.983333. Nice small bug to let them hit.
  • e.repeat. Not taught in class, so don't require it — but expect the bug it fixes. Holding P for half a second toggles pause ~15 times and looks like a flickering ghost. It's a great "why is this happening?" moment; the answer is the same OS key-repeat that Session 10 warned about, showing up in a new place.
🔑 Draw keeps running while paused — deliberately
Only update() is guarded. draw() carries on so the PAUSED banner can appear. If a student guards the loop itself, the screen freezes on whatever was last painted and the banner never shows. Ask them: "Which of your two functions is allowed to change things? So which one should the pause switch off?"
⚠️ Expect this one
Symptom: everything smears into coloured trails. Cause: no clearRect. What to ask instead: "The canvas doesn't wipe itself between frames. So what's on screen right now — one drawing, or hundreds?"

Fly the tug

Sessions 10, 6~20 min
const tug = { x: 60, y: H - 80, w: TUG_W, h: TUG_H, speed: TUG_SPEED };
const keys = {};                    // the notepad: which keys are held RIGHT NOW

document.addEventListener("keydown", function (e) {
  keys[e.key] = true;
  if (e.key === "ArrowUp" || e.key === "ArrowDown" ||
      e.key === "ArrowLeft" || e.key === "ArrowRight") {
    e.preventDefault();             // stop the arrows scrolling the page
  }
  /* ...the P and R handling from Stage 2 lives here too... */
});

document.addEventListener("keyup", function (e) {
  keys[e.key] = false;
});

// Session 10's stuck-key fix: lose focus, forget every key.
window.addEventListener("blur", function () {
  for (const k in keys) { keys[k] = false; }
});

function moveTug() {
  if (keys["ArrowLeft"])  { tug.x -= tug.speed; }   // four SEPARATE ifs —
  if (keys["ArrowRight"]) { tug.x += tug.speed; }   // no else, so diagonals
  if (keys["ArrowUp"])    { tug.y -= tug.speed; }   // work for free
  if (keys["ArrowDown"])  { tug.y += tug.speed; }

  // clamp: x is the LEFT corner, so the far limit is W minus our own width
  tug.x = Math.max(0, Math.min(W - tug.w, tug.x));
  tug.y = Math.max(0, Math.min(H - tug.h, tug.y));
}

Why it's written this way

  • Four separate ifs, no else. That's the entire reason diagonals work. If they used else if, only one direction fires per frame and the tug refuses to move diagonally — a symptom that looks mysterious until you look at the word else.
  • Listeners on document, not the canvas. Session 10 used the canvas with tabindex so keys only worked after clicking it. Here the mouse has its own job, so demanding a click to arm the keyboard would be annoying. Listening on document removes the focus problem entirely — and it's worth telling them that this is a design choice, not a rule.
  • The clamp reads inside-out. W - tug.w is 674: the furthest left-corner position that still keeps all 46 pixels on screen. Math.min handles the right wall, Math.max the left. Two walls, one line, per axis.
  • The blur listener is the stuck-key fix from Session 10. Not strictly required by the spec, but if they included it unprompted, say something — it means the lesson landed.
⚠️ Expect these two
Symptom: movement stutters — moves, pauses, then races. Cause: they moved the tug inside the keydown handler instead of in update(). What to ask instead: "Hold a letter down in a text box and watch. Where's your movement getting its timing from — your loop, or the keyboard?"

Symptom: tug hangs off the right edge by exactly its own width. Cause: clamped against W instead of W - tug.w. What to ask instead: "When x is 719, where does the rectangle start, and where does it end?"

Cargo pods: arrays, loops and collecting

Sessions 7, 12, 5The hardest stage
let pods = [];

function randomBetween(min, max) {
  return min + Math.random() * (max - min);
}

function distance(ax, ay, bx, by) {
  const dx = ax - bx;
  const dy = ay - by;
  return Math.sqrt(dx * dx + dy * dy);
}

function rectsOverlap(a, b) {
  return a.x < b.x + b.w &&      // a's left is before b's right
         a.x + a.w > b.x &&      // a's right is past b's left
         a.y < b.y + b.h &&      // a's top is above b's bottom
         a.y + a.h > b.y;        // a's bottom is below b's top
}

// Keep guessing until the spot is legal. "Try, check, try again."
function makePod() {
  let pod = null;
  let safe = false;
  while (safe === false) {
    pod = {
      x: randomBetween(0, W - POD_SIZE),
      y: randomBetween(HUD_H, H - POD_SIZE),   // HUD_H keeps it out of the text
      w: POD_SIZE,
      h: POD_SIZE
    };
    const gap = distance(pod.x + POD_SIZE / 2, pod.y + POD_SIZE / 2, core.x, core.y);
    if (gap > POD_SAFE_GAP) { safe = true; }
  }
  return pod;
}

function spawnWave() {
  pods = [];
  for (let i = 0; i < PODS_PER_WAVE; i++) {
    pods.push(makePod());
  }
  console.log("Wave " + wave + " — pods: " + pods.length);
}

function checkPodPickups() {
  // BACKWARDS. This is the whole trick. See the note below.
  for (let i = pods.length - 1; i >= 0; i--) {
    if (rectsOverlap(tug, pods[i])) {
      score += SCORE_POD;
      pods.splice(i, 1);
    }
  }
  if (pods.length === 0) {          // wave cleared
    score += SCORE_WAVE;
    wave++;
    spawnWave();
    rocks.push(makeRock());         // the difficulty ramp (added in Stage 5)
  }
}
🐛 The backwards loop — the most valuable ten minutes in the project

Going forwards, removing item 3 shifts item 4 down into slot 3 — and then i++ moves past it. The next pod is skipped. Two pods touching, only one collected, and it looks like the collision test is broken when it's perfect.

Counting backwards fixes it because everything that shifts is behind you; you've already been there.

What to ask instead of telling them: "Put a console.log(i, pods.length) inside the loop and collect two pods at once. Read the numbers out to me." They will see the loop end early. Let them get there — this bug teaches more than the rest of the stage combined.

The other valid fix: mark pods with collected = true during the loop and remove them after. Equally correct. Accept it and ask them to explain why it dodges the problem.

Why the rest is written this way

  • The "try, check, try again" spawn loop. Beginners reach for clever maths to place pods outside a circle. The honest answer is to guess and re-guess — it's three lines and it always works. Worth naming out loud: rejection sampling, used in real games constantly.
  • Measure the pod's centre, not its corner, when checking distance from the core — hence + POD_SIZE / 2. Corner-based measuring works too but lets pods creep slightly closer on one side. Minor; mention only if they ask.
  • HUD_H stops pods spawning under the score line where they're hard to see. Small detail, and a good example of a "game feel" fix that isn't a bug fix.
  • The wave check sits at the bottom of the same function. Some students put it in update() instead — fine, as long as it runs after pickups, not before.
💡 If collisions "don't work", make them visible
ctx.strokeRect(...) around both boxes being tested. The picture reveals a wrong width or a wrong corner in seconds. Teach this as the reflex — it's the single most useful debugging habit in 2D game development.

The rock field: velocity and bouncing

Sessions 9, 7, 6~30 min
let rocks = [];

// A speed that is never zero: pick a SIZE, then pick a DIRECTION.
function randomSpeed() {
  const size = randomBetween(ROCK_MIN_SPEED, ROCK_MAX_SPEED);
  if (Math.random() < 0.5) { return -size; }
  return size;
}

// Returns a new rock on a random edge, always drifting INWARDS.
function makeRock() {
  const r = randomBetween(ROCK_MIN_R, ROCK_MAX_R);
  const rock = { x: 0, y: 0, r: r, vx: randomSpeed(), vy: randomSpeed(), unstable: false };
  const edge = Math.floor(randomBetween(0, 4));    // 0 top, 1 right, 2 bottom, 3 left

  if (edge === 0) {
    rock.x = randomBetween(r, W - r); rock.y = r;          rock.vy = Math.abs(rock.vy);
  } else if (edge === 1) {
    rock.x = W - r;  rock.y = randomBetween(r, H - r);      rock.vx = -Math.abs(rock.vx);
  } else if (edge === 2) {
    rock.x = randomBetween(r, W - r); rock.y = H - r;       rock.vy = -Math.abs(rock.vy);
  } else {
    rock.x = r;      rock.y = randomBetween(r, H - r);      rock.vx = Math.abs(rock.vx);
  }
  return rock;
}

function moveRocks() {
  for (let i = 0; i < rocks.length; i++) {
    const rock = rocks[i];
    rock.x += rock.vx;
    rock.y += rock.vy;

    // A circle's edge is x - r and x + r, NOT x.
    // Fix the position AND flip the velocity, or it sticks and vibrates.
    if (rock.x - rock.r < 0) { rock.x = rock.r;     rock.vx = -rock.vx; }
    if (rock.x + rock.r > W) { rock.x = W - rock.r; rock.vx = -rock.vx; }
    if (rock.y - rock.r < 0) { rock.y = rock.r;     rock.vy = -rock.vy; }
    if (rock.y + rock.r > H) { rock.y = H - rock.r; rock.vy = -rock.vy; }
  }
}

Why it's written this way

  • Position fixed and velocity flipped. Flipping alone leaves the rock still overlapping the wall next frame, so it flips again, and again — the classic vibrating-stuck-rock. "Flip the velocity, then fix the position" is the sentence to make them say out loud, because Pong needs exactly this in Session 13.
  • rock.x - rock.r, not rock.x. Circles measure from the centre. Get it wrong and rocks sink half-in before turning. Very visible once pointed at, nearly invisible before.
  • randomSpeed() picks a size then a sign. The naive randomBetween(-2.5, 2.5) can produce something like 0.02 — a rock that appears frozen and reads as a bug. Splitting size from direction guarantees a real minimum speed. This is the spec's "decide how you'll prevent that", and any solution that guarantees a floor is correct.
  • Rocks spawn on an edge, aimed inwards. Two reasons: replacements arriving mid-screen look like teleporting, and a rock spawned at a random interior point could land on top of the core and take a shield point instantly.
  • makeRock() must be called once per rock. Watch for a student calling it once and pushing the same object three times — three rocks that move as one. A nice, concrete demonstration of what an object reference is.
🎯 Optional depth, only if they're flying
Ask why the rocks all move at slightly different speeds even though the loop runs at one rate. Answer: speed lives in the object, not the loop. That's the idea that later lets one game hold a hundred things all behaving differently.

Rocks hit the core: circle collision and consequences

Sessions 12, 11, 6~25 min
let flash = 0;    // frames of red left on the core after a hit

function circlesOverlap(a, b) {
  return distance(a.x, a.y, b.x, b.y) < a.r + b.r;
}

function checkCoreHits() {
  for (let i = rocks.length - 1; i >= 0; i--) {     // backwards again — we splice
    const rock = rocks[i];
    if (circlesOverlap(rock, core)) {
      if (rock.unstable === true) {
        core.shield -= DAMAGE_UNSTABLE;
      } else {
        core.shield -= DAMAGE_NORMAL;
      }
      flash = 12;                  // about a fifth of a second of red
      rocks.splice(i, 1);          // REMOVE IT — or it damages us every frame
      rocks.push(makeRock());      // and send a replacement in from an edge
    }
  }
}

function checkEndConditions() {
  if (core.shield <= 0) {
    core.shield = 0;               // never draw a negative shield
    gameOver = true;
    endReason = "SHIELD DOWN";
  } else if (timeLeft() <= 0) {
    gameOver = true;
    endReason = "TIME UP";
  }
}

function resetGame() {
  score = 0; wave = 1; frames = 0; flash = 0;
  paused = false; gameOver = false; endReason = "";
  core.shield = START_SHIELD;
  tug.x = 60; tug.y = H - 80;
  rocks = [];
  for (let i = 0; i < START_ROCKS; i++) { rocks.push(makeRock()); }
  spawnWave();
}

Why it's written this way

  • circlesOverlap is three words long because distance already exists. Point at this. The function they wrote for a mouse click in Session 11 is now deciding whether a rock hit a space station. That's the whole argument for writing functions, in one visible line.
  • Remove the rock on impact. Otherwise it sits inside the core overlapping for 20 frames and drains 20 shield in a third of a second. Every student hits some version of this — the general lesson is that a collision lasts many frames unless something changes, and that's exactly why a bounce reverses velocity rather than just noting the hit.
  • Splice then push, inside a backwards loop. Safe: the pushed rock lands at the end of the array, above the current index, and the loop is walking down. If they push inside a forwards loop they can end up testing the brand-new rock in the same frame.
  • core.shield = 0 before ending. Cosmetic, but an unstable rock hitting a 2-shield core would otherwise print -1 on the end screen.
  • resetGame() touches every single piece of state. The commonest miss is frames — the game restarts with 12 seconds left. Second commonest is gameOver itself, which makes R appear to do nothing at all.
⚠️ Expect this one
Symptom: R works mid-game but not on the game-over screen. Cause: the key handling was put inside update(), which the guard has switched off. What to ask instead: "When the game is over, what's the very first thing update() does? So who's listening for your R?"

Unstable rocks and the mouse

Sessions 11, 6, 7~25 min
function maybeDestabilise() {
  if (frames % (UNSTABLE_EVERY * FPS) !== 0) { return; }   // not a 5-second mark
  if (rocks.length === 0) { return; }
  const i = Math.floor(randomBetween(0, rocks.length));     // pick ONE at random
  rocks[i].unstable = true;
}

// THE Session 11 function. Window coordinates -> canvas coordinates.
function getMousePos(event) {
  const rect = canvas.getBoundingClientRect();
  return {
    x: event.clientX - rect.left,
    y: event.clientY - rect.top
  };
}

canvas.addEventListener("click", function (event) {
  if (paused === true || gameOver === true) { return; }
  const pos = getMousePos(event);

  // Backwards, so the rock drawn on TOP is the one that gets tested first.
  for (let i = rocks.length - 1; i >= 0; i--) {
    const rock = rocks[i];
    if (distance(pos.x, pos.y, rock.x, rock.y) < rock.r) {   // point-in-circle
      if (rock.unstable === true) {
        score += SCORE_VAPORISE;
        rocks.splice(i, 1);
        rocks.push(makeRock());
      } else {
        score = Math.max(0, score - SCORE_MISCLICK);          // never below zero
      }
      return;      // stop! one click affects at most ONE rock
    }
  }
});

Why it's written this way

  • frames % 300 !== 0 then return. Another guard. Because frames only advances when unpaused, "every 5 seconds" means five seconds of played time — pausing doesn't hand you free rocks.
  • The click loop runs backwards for a different reason than Stage 4. Here it's about draw order: the last rock drawn sits on top, so it should be the one a click lands on. Different problem, same tool — worth naming so they don't think "backwards" is a superstition.
  • The return after handling a hit is load-bearing. Without it, one click on a spot where two rocks overlap charges them twice, or vaporises one and penalises them for the other. Ask them to predict what happens before they add it.
  • Math.max(0, score - 5). The spec's floor-at-zero rule. if (score < 0) { score = 0; } is equally fine.
  • Clicks ignored while paused or over. Self-test #5 checks it. Without the guard you can farm points on the game-over screen.
🐛 The offset bug — and how to prove it's the offset

Symptom: clicks miss, consistently, by the same amount. Cause: no getBoundingClientRect conversion. It may be invisible if the canvas happens to sit near the top-left — have them scroll the page down and try again, and the error grows with the scroll.

What to ask instead: "Log the position you calculated and the position of the rock you aimed at. Are the two numbers different by roughly the same amount every time?"

⚠️ Also expect
Symptom: every rock goes unstable at once. Cause: they looped all rocks instead of picking one, or the "every 5 seconds" test is true for a whole second's worth of frames (e.g. comparing seconds rather than frames). What to ask instead: "How many frames in a row is your condition true for?"
STAGE
8

Difficulty, polish, and the clean-up pass

All sessionsWorth 20 marks

The finished update() — this is the target

function update() {
  if (paused === true || gameOver === true) { return; }
  frames++;
  if (flash > 0) { flash--; }
  moveTug();
  moveRocks();
  checkPodPickups();
  checkCoreHits();
  maybeDestabilise();
  checkEndConditions();
}

Nine lines of body, and it reads as a sentence: move the player, move the rocks, check pickups, check damage, maybe destabilise something, check whether we're done. Every one of those is a function they can open, understand and fix on its own.

What "polish" should actually contain

  • The difficulty ramp is already in checkPodPickups — one rocks.push(makeRock()) on wave clear. By wave three there are six rocks and the game bites.
  • Damage feedback: the reference uses a flash counter set to 12 on impact and decremented each frame, with the core drawn red while it's above zero. This "count down a number, react while it's positive" pattern is how every hit-flash, invulnerability window and power-up timer works. Point that out — it's a bigger idea than it looks.
  • Low-shield warning: HUD text turns red at 3 or below. One if, big effect.

Marking the clean-up pass

Four questions, and you can answer all of them by scrolling their file for two minutes:

  1. Is there any number below the settings block that a player would want to tune? (Layout values like 14 for text position don't count.)
  2. Is any function longer than about 20 lines?
  3. Is any block of code repeated nearly identically twice?
  4. Does every function have a one-line comment saying what it's for, rather than restating what the code does?
🔑 Protect this stage
Students stop the moment it works, and this is where the professional habits live. Tell them up front that the clean-up pass and self-test are 20 of the 100 marks. That one sentence is usually enough.

game.js — the whole thing (about 330 lines with comments)
// ===============================================================
//  SALVAGE RUN — Station Kepler
//  Reference solution · Game Dev Pro · Sessions 1–12
//  Written using ONLY what the student has been taught.
// ===============================================================

console.log("Salvage Run booting…");

// ---------------------------------------------------------------
//  1. THE CANVAS
// ---------------------------------------------------------------
const canvas = document.getElementById("game");
const ctx = canvas.getContext("2d");
const W = canvas.width;
const H = canvas.height;

// ---------------------------------------------------------------
//  2. SETTINGS — every tunable number lives here and NOWHERE else
// ---------------------------------------------------------------
const FPS = 60;                 // frames per second (what rAF gives us)
const ROUND_SECONDS = 60;       // length of one run

const TUG_W = 46;
const TUG_H = 26;
const TUG_SPEED = 5;

const POD_SIZE = 18;
const PODS_PER_WAVE = 8;
const POD_SAFE_GAP = 90;        // pods must spawn this far from the core
const HUD_H = 40;               // keep pods from spawning under the HUD text

const START_ROCKS = 3;
const ROCK_MIN_R = 12;
const ROCK_MAX_R = 26;
const ROCK_MIN_SPEED = 0.8;     // never zero — a still rock looks broken
const ROCK_MAX_SPEED = 2.5;
const UNSTABLE_EVERY = 5;       // seconds between one rock going unstable

const CORE_R = 44;
const START_SHIELD = 10;
const DAMAGE_NORMAL = 1;
const DAMAGE_UNSTABLE = 3;

const SCORE_POD = 10;
const SCORE_WAVE = 50;
const SCORE_VAPORISE = 25;
const SCORE_MISCLICK = 5;       // subtracted for clicking a stable rock

// colours
const COL_TUG = "#34d399";
const COL_POD = "#6c8cff";
const COL_ROCK = "#a3aad6";
const COL_UNSTABLE = "#fbbf24";
const COL_CORE = "#9a6bff";
const COL_TEXT = "#e9ecff";
const COL_BAD = "#fb7185";

// ---------------------------------------------------------------
//  3. STATE — the things that change while the game runs
// ---------------------------------------------------------------
let score = 0;
let wave = 1;
let frames = 0;                 // counts only UNPAUSED frames
let paused = false;
let gameOver = false;
let endReason = "";
let flash = 0;                  // counts down after damage, for the red flash

let pods = [];
let rocks = [];

const tug = { x: 60, y: H - 80, w: TUG_W, h: TUG_H, speed: TUG_SPEED };
const core = { x: W / 2, y: H / 2, r: CORE_R, shield: START_SHIELD };
const keys = {};                // which keys are held down right now

// ---------------------------------------------------------------
//  4. LITTLE HELPERS (the four that return a value)
// ---------------------------------------------------------------

// A random decimal between min and max.
function randomBetween(min, max) {
  return min + Math.random() * (max - min);
}

// Straight-line distance between two points (Pythagoras).
function distance(ax, ay, bx, by) {
  const dx = ax - bx;
  const dy = ay - by;
  return Math.sqrt(dx * dx + dy * dy);
}

// Do two rectangles overlap? (AABB — four comparisons.)
function rectsOverlap(a, b) {
  return a.x < b.x + b.w &&
         a.x + a.w > b.x &&
         a.y < b.y + b.h &&
         a.y + a.h > b.y;
}

// Do two circles overlap? (Centres closer than the two radii added up.)
function circlesOverlap(a, b) {
  return distance(a.x, a.y, b.x, b.y) < a.r + b.r;
}

// How many whole seconds are left in the round.
function timeLeft() {
  return Math.max(0, ROUND_SECONDS - Math.floor(frames / FPS));
}

// ---------------------------------------------------------------
//  5. DRAWING HELPERS
// ---------------------------------------------------------------
function drawRect(r, colour) {
  ctx.fillStyle = colour;
  ctx.fillRect(r.x, r.y, r.w, r.h);
}

function drawCircle(c, colour) {
  ctx.fillStyle = colour;
  ctx.beginPath();
  ctx.arc(c.x, c.y, c.r, 0, Math.PI * 2);
  ctx.fill();
}

// ---------------------------------------------------------------
//  6. MAKING THINGS
// ---------------------------------------------------------------

// A speed that is never zero: pick a size, then pick a direction.
function randomSpeed() {
  const size = randomBetween(ROCK_MIN_SPEED, ROCK_MAX_SPEED);
  if (Math.random() < 0.5) {
    return -size;
  }
  return size;
}

// Returns a brand-new rock, sitting on a random edge, drifting inwards.
function makeRock() {
  const r = randomBetween(ROCK_MIN_R, ROCK_MAX_R);
  const rock = { x: 0, y: 0, r: r, vx: randomSpeed(), vy: randomSpeed(), unstable: false };
  const edge = Math.floor(randomBetween(0, 4));   // 0 top, 1 right, 2 bottom, 3 left

  if (edge === 0) {
    rock.x = randomBetween(r, W - r);
    rock.y = r;
    rock.vy = Math.abs(rock.vy);            // must head DOWN, into the sector
  } else if (edge === 1) {
    rock.x = W - r;
    rock.y = randomBetween(r, H - r);
    rock.vx = -Math.abs(rock.vx);           // must head LEFT
  } else if (edge === 2) {
    rock.x = randomBetween(r, W - r);
    rock.y = H - r;
    rock.vy = -Math.abs(rock.vy);           // must head UP
  } else {
    rock.x = r;
    rock.y = randomBetween(r, H - r);
    rock.vx = Math.abs(rock.vx);            // must head RIGHT
  }
  return rock;
}

// Returns one pod in a legal spot: on screen, below the HUD, away from the core.
function makePod() {
  let pod = null;
  let safe = false;
  while (safe === false) {
    pod = {
      x: randomBetween(0, W - POD_SIZE),
      y: randomBetween(HUD_H, H - POD_SIZE),
      w: POD_SIZE,
      h: POD_SIZE
    };
    const gap = distance(pod.x + POD_SIZE / 2, pod.y + POD_SIZE / 2, core.x, core.y);
    if (gap > POD_SAFE_GAP) {
      safe = true;
    }
  }
  return pod;
}

// Fills the pods array with a fresh wave.
function spawnWave() {
  pods = [];
  for (let i = 0; i < PODS_PER_WAVE; i++) {
    pods.push(makePod());
  }
  console.log("Wave " + wave + " — pods: " + pods.length);
}

// Puts every single thing back to its starting value.
function resetGame() {
  score = 0;
  wave = 1;
  frames = 0;
  flash = 0;
  paused = false;
  gameOver = false;
  endReason = "";
  core.shield = START_SHIELD;
  tug.x = 60;
  tug.y = H - 80;
  rocks = [];
  for (let i = 0; i < START_ROCKS; i++) {
    rocks.push(makeRock());
  }
  spawnWave();
}

// ---------------------------------------------------------------
//  7. INPUT
// ---------------------------------------------------------------
document.addEventListener("keydown", function (e) {
  keys[e.key] = true;

  // stop the arrow keys scrolling the page
  if (e.key === "ArrowUp" || e.key === "ArrowDown" ||
      e.key === "ArrowLeft" || e.key === "ArrowRight") {
    e.preventDefault();
  }

  // e.repeat is true when the key is auto-repeating from being held.
  // Without this check, holding P flickers the pause on and off.
  if (e.repeat === false) {
    if (e.key === "p" || e.key === "P") {
      paused = !paused;
    }
    if (e.key === "r" || e.key === "R") {
      resetGame();
    }
  }
});

document.addEventListener("keyup", function (e) {
  keys[e.key] = false;
});

// If the window loses focus, forget every held key (Session 10's stuck-key fix).
window.addEventListener("blur", function () {
  for (const k in keys) {
    keys[k] = false;
  }
});

// Convert a mouse event into CANVAS coordinates. The whole point of Session 11.
function getMousePos(event) {
  const rect = canvas.getBoundingClientRect();
  return {
    x: event.clientX - rect.left,
    y: event.clientY - rect.top
  };
}

canvas.addEventListener("click", function (event) {
  if (paused === true || gameOver === true) {
    return;
  }
  const pos = getMousePos(event);

  // Backwards, so we test the rock drawn on TOP first.
  for (let i = rocks.length - 1; i >= 0; i--) {
    const rock = rocks[i];
    if (distance(pos.x, pos.y, rock.x, rock.y) < rock.r) {
      if (rock.unstable === true) {
        score += SCORE_VAPORISE;
        rocks.splice(i, 1);
        rocks.push(makeRock());
      } else {
        score = Math.max(0, score - SCORE_MISCLICK);
      }
      return;                 // one click affects at most ONE rock
    }
  }
});

// ---------------------------------------------------------------
//  8. UPDATE — the rules of the world, one frame at a time
// ---------------------------------------------------------------
function moveTug() {
  if (keys["ArrowLeft"])  { tug.x -= tug.speed; }
  if (keys["ArrowRight"]) { tug.x += tug.speed; }
  if (keys["ArrowUp"])    { tug.y -= tug.speed; }
  if (keys["ArrowDown"])  { tug.y += tug.speed; }

  // clamp: x is the LEFT corner, so the limit is the width minus our own width
  tug.x = Math.max(0, Math.min(W - tug.w, tug.x));
  tug.y = Math.max(0, Math.min(H - tug.h, tug.y));
}

function moveRocks() {
  for (let i = 0; i < rocks.length; i++) {
    const rock = rocks[i];
    rock.x += rock.vx;
    rock.y += rock.vy;

    // A circle's edge is x - r and x + r, NOT x.
    // Fix the position first, then flip the velocity — otherwise it sticks.
    if (rock.x - rock.r < 0) { rock.x = rock.r;     rock.vx = -rock.vx; }
    if (rock.x + rock.r > W) { rock.x = W - rock.r; rock.vx = -rock.vx; }
    if (rock.y - rock.r < 0) { rock.y = rock.r;     rock.vy = -rock.vy; }
    if (rock.y + rock.r > H) { rock.y = H - rock.r; rock.vy = -rock.vy; }
  }
}

function checkPodPickups() {
  // BACKWARDS, because we remove items as we go.
  for (let i = pods.length - 1; i >= 0; i--) {
    if (rectsOverlap(tug, pods[i])) {
      score += SCORE_POD;
      pods.splice(i, 1);
    }
  }
  if (pods.length === 0) {          // wave cleared
    score += SCORE_WAVE;
    wave++;
    spawnWave();
    rocks.push(makeRock());         // the difficulty ramp
  }
}

function checkCoreHits() {
  for (let i = rocks.length - 1; i >= 0; i--) {
    const rock = rocks[i];
    if (circlesOverlap(rock, core)) {
      if (rock.unstable === true) {
        core.shield -= DAMAGE_UNSTABLE;
      } else {
        core.shield -= DAMAGE_NORMAL;
      }
      flash = 12;                   // 12 frames of red = about a fifth of a second
      rocks.splice(i, 1);           // remove it, or it damages us every frame
      rocks.push(makeRock());       // and send a replacement in from an edge
    }
  }
}

function maybeDestabilise() {
  if (frames % (UNSTABLE_EVERY * FPS) !== 0) { return; }   // not time yet
  if (rocks.length === 0) { return; }
  const i = Math.floor(randomBetween(0, rocks.length));
  rocks[i].unstable = true;
}

function checkEndConditions() {
  if (core.shield <= 0) {
    core.shield = 0;
    gameOver = true;
    endReason = "SHIELD DOWN";
  } else if (timeLeft() <= 0) {
    gameOver = true;
    endReason = "TIME UP";
  }
}

function update() {
  if (paused === true || gameOver === true) { return; }   // the guard
  frames++;
  if (flash > 0) { flash--; }
  moveTug();
  moveRocks();
  checkPodPickups();
  checkCoreHits();
  maybeDestabilise();
  checkEndConditions();
}

// ---------------------------------------------------------------
//  9. DRAW — paint the world, change nothing
// ---------------------------------------------------------------
function drawCore() {
  // faint danger ring
  ctx.strokeStyle = COL_CORE;
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(core.x, core.y, core.r + 10, 0, Math.PI * 2);
  ctx.stroke();

  if (flash > 0) {
    drawCircle(core, COL_BAD);
  } else {
    drawCircle(core, COL_CORE);
  }

  ctx.fillStyle = COL_TEXT;
  ctx.font = "20px system-ui";
  ctx.textAlign = "center";
  ctx.fillText(core.shield, core.x, core.y + 7);
  ctx.textAlign = "left";
}

function drawHud() {
  const line = "Score: " + score +
               "    Wave: " + wave +
               "    Pods: " + pods.length +
               "    Shield: " + core.shield +
               "    Time: " + timeLeft();
  if (core.shield <= 3) {
    ctx.fillStyle = COL_BAD;
  } else {
    ctx.fillStyle = COL_TEXT;
  }
  ctx.font = "17px system-ui";
  ctx.fillText(line, 14, 28);
}

function drawBanner(big, small) {
  ctx.fillStyle = "rgba(5, 7, 20, 0.72)";
  ctx.fillRect(0, H / 2 - 60, W, 120);
  ctx.textAlign = "center";
  ctx.fillStyle = COL_TEXT;
  ctx.font = "34px system-ui";
  ctx.fillText(big, W / 2, H / 2 - 6);
  ctx.font = "16px system-ui";
  ctx.fillStyle = COL_ROCK;
  ctx.fillText(small, W / 2, H / 2 + 28);
  ctx.textAlign = "left";
}

function draw() {
  ctx.clearRect(0, 0, W, H);          // ALWAYS first

  drawCore();

  for (let i = 0; i < pods.length; i++) {
    drawRect(pods[i], COL_POD);
  }
  for (let i = 0; i < rocks.length; i++) {
    if (rocks[i].unstable === true) {
      drawCircle(rocks[i], COL_UNSTABLE);
    } else {
      drawCircle(rocks[i], COL_ROCK);
    }
  }

  drawRect(tug, COL_TUG);
  drawHud();

  if (paused === true) {
    drawBanner("PAUSED", "Press P to carry on");
  }
  if (gameOver === true) {
    drawBanner(endReason, "Final score " + score + " — press R to fly again");
  }
}

// ---------------------------------------------------------------
//  10. THE LOOP
// ---------------------------------------------------------------
function loop() {
  update();
  draw();
  requestAnimationFrame(loop);
}

resetGame();
requestAnimationFrame(loop);
🎯 A note on the dialect
This solution deliberately uses only what has been taught: classic for loops, function (e) { } listeners rather than arrows, if/else rather than ternaries, and string joining with + rather than template literals. If a student arrives with arrow functions or forEach because they've been reading ahead, that's a good sign — accept it, and ask them to explain what it does.

Oral questions — the answers you're listening for

  1. A function that returns something. Any of randomBetween, distance, rectsOverlap, circlesOverlap, makeRock, timeLeft. Full marks if they can name the caller too — e.g. circlesOverlap uses what distance returns.
  2. Why the right-hand limit isn't W. Because x is the left corner and the rectangle is drawn rightwards from it, so it must stop one width early: W - tug.w.
  3. Three uses of distance. The click-vs-rock test, the rock-vs-core test (inside circlesOverlap), and keeping new pods clear of the core.
  4. Deleting clearRect. Every frame paints on top of the last — trails everywhere, and the core's shield number turns into unreadable overlapping digits.
  5. Circle vs rectangle anchors. arc draws from the centre, fillRect from the top-left corner. So a rock's left edge is x - r, a pod's is just x.
  6. One frame, in order. Guard → frames++ → move tug → move rocks → check pickups → check core hits → maybe destabilise → check end → clear → draw everything → ask for the next frame. Anything close, in a sensible order, is a pass.
  7. const vs let. Settings and the objects themselves are const; score, wave, frames, the booleans and the arrays are let. The score can't be const because the name gets pointed at a brand-new number each time it changes. Bonus marks for noticing core is const while core.shield changes.
  8. Two touching pods. Loop backwards (or mark-then-remove), because removing an item shifts everything after it down a slot.
  9. Clicks 40px off. getMousePos — the getBoundingClientRect subtraction. Extra credit for "and I'd scroll the page to confirm it's an offset".
  10. Code they're unhappy with. No right answer. You're testing whether they can look at their own work critically. "It all seems fine" from a student with a 60-line update() is itself the finding.
💡 The single best predictor
Question 6 — walking through one frame in order. A student who can narrate a frame understands the architecture and will cope with Pong. A student who can't will struggle no matter how well their game runs, and the fix is to rebuild the Stage 2 skeleton with them, not to add more features.
