🚁 Challenge 1 — The Patrol Drone · Session 9

The skill being tested: that a bounce is a rule about a boundary, not something canvases do. They've only ever bounced off the screen edge; here the boundary is two arbitrary posts, so nothing can be copied without understanding.

The answer

    function update() {
      drone.x += drone.vx;                    // position += velocity

      // The drone's RIGHT edge is x + w, not x.
      if (drone.x + drone.w > RIGHT_POST) {
        drone.x = RIGHT_POST - drone.w;       // 1. fix the position
        drone.vx = -drone.vx;                 // 2. then flip the velocity
      }
      // The drone's LEFT edge is just x.
      if (drone.x < LEFT_POST) {
        drone.x = LEFT_POST;
        drone.vx = -drone.vx;
      }
    }

Why each line is there

  • drone.x + drone.w for the right test, plain drone.x for the left. The asymmetry is the point. A rectangle is drawn rightwards from its corner, so only one of its two edges is the value you're storing.
  • Position fixed before the velocity flips. Flipping alone leaves it past the post on the next frame too. With vx = 3 the overshoot is small enough to look like a rendering wobble; crank the speed to 20 and it becomes obvious.
  • Two separate ifs, no else. Not strictly required here, but if they use else if it still works — worth asking whether it could ever matter. (It can, if the patrol gap is narrower than one frame of movement.)
  • vx is drawn on screen on purpose. The number visibly flips between 3 and −3, which makes "the sign is the direction" concrete rather than abstract.

Wrong turns, and what to ask

What you'll seeCauseAsk them

🔑 The sentence to make them say
"Flip the velocity, then fix the position." They will need it again in Pong, and in Breakout, and every time anything ever bounces. If they leave today's session able to say it and explain it, the challenge did its job.
Stretch answers

1. Two axes. Add vy: 2, then drone.y += drone.vy and the same fix-then-flip against 0 and H - drone.h. Note that the posts only limit x — vertical uses the canvas. Two different kinds of boundary in one object is exactly the insight.

2. A second drone. They pass straight through each other, because nothing in the code knows the other exists. That's a genuinely useful realisation: collisions do not happen unless you write them. Session 12 is where that gets fixed — flag it.

3. Speed trap. Once |vx| exceeds the gap between the posts (300px), one frame carries it clean past both, and the two ifs can fight each other — it jitters, escapes, or freezes. Long before that, at around 40–60px per frame, it visibly teleports rather than moves. The lesson: a collision check only works if things move less than the thing they might hit. Real engines call this tunnelling. Excellent conversation if they get there.

  <script>
    const canvas = document.getElementById("game");
    const ctx = canvas.getContext("2d");
    const W = canvas.width, H = canvas.height;

    // ---- the patrol route (NOT the canvas edges) ----
    const LEFT_POST = 60;
    const RIGHT_POST = 360;

    const drone = { x: 100, y: 88, w: 40, h: 26, vx: 3 };

    // ================= THE ANSWER =================
    function update() {
      drone.x += drone.vx;                    // position += velocity

      // The drone's RIGHT edge is x + w, not x.
      if (drone.x + drone.w > RIGHT_POST) {
        drone.x = RIGHT_POST - drone.w;       // 1. fix the position
        drone.vx = -drone.vx;                 // 2. then flip the velocity
      }
      // The drone's LEFT edge is just x.
      if (drone.x < LEFT_POST) {
        drone.x = LEFT_POST;
        drone.vx = -drone.vx;
      }
    }
    // =============================================

    function drawPost(x) {
      ctx.strokeStyle = "#fbbf24";
      ctx.lineWidth = 3;
      ctx.beginPath();
      ctx.moveTo(x, 40);
      ctx.lineTo(x, H - 40);
      ctx.stroke();
    }

    function draw() {
      ctx.clearRect(0, 0, W, H);
      drawPost(LEFT_POST);
      drawPost(RIGHT_POST);
      ctx.fillStyle = "#34d399";
      ctx.fillRect(drone.x, drone.y, drone.w, drone.h);
      ctx.fillStyle = "#e9ecff";
      ctx.font = "14px system-ui";
      ctx.fillText("vx: " + drone.vx, 12, 24);
    }

    function loop() { update(); draw(); requestAnimationFrame(loop); }
    requestAnimationFrame(loop);
  </script>
</body>

🛰️ Challenge 2 — Docking Bay · Session 10

The skill being tested: the held-keys pattern used for something other than plain movement. The Shift modifier proves they understand that keys is just a record they can ask any question of — and "fully inside" forces them to reason about edges rather than recall a formula.

The answer

    const keys = {};

    canvas.addEventListener("keydown", function (e) {
      keys[e.key] = true;
      e.preventDefault();          // stop the arrows scrolling the page
    });
    canvas.addEventListener("keyup", function (e) {
      keys[e.key] = false;
    });
    canvas.addEventListener("blur", function () {
      for (const k in keys) { keys[k] = false; }   // forget everything on focus loss
    });

    // FULLY inside means all four edges are within the bay's four edges.
    function isDocked() {
      return shuttle.x >= bay.x &&
             shuttle.x + shuttle.w <= bay.x + bay.w &&
             shuttle.y >= bay.y &&
             shuttle.y + shuttle.h <= bay.y + bay.h;
    }

    function update() {
      let speed = NORMAL_SPEED;
      if (keys["Shift"]) { speed = PRECISION_SPEED; }   // Shift is just another key

      if (keys["ArrowLeft"])  { shuttle.x -= speed; }
      if (keys["ArrowRight"]) { shuttle.x += speed; }
      if (keys["ArrowUp"])    { shuttle.y -= speed; }
      if (keys["ArrowDown"])  { shuttle.y += speed; }

      shuttle.x = Math.max(0, Math.min(W - shuttle.w, shuttle.x));
      shuttle.y = Math.max(0, Math.min(H - shuttle.h, shuttle.y));

      docked = isDocked();
    }

Why each line is there

  • let speed = NORMAL_SPEED; then maybe reassign. One variable used by all four directions. Watch for the student who writes eight ifs — four for normal, four for precision. It works; it's also the moment to teach "decide the value first, then use it once".
  • keys["Shift"] needs no special handling. A modifier key is an ordinary key in an ordinary notepad. That's the "think about it" question on their sheet, and the answer is: there is no difference in the code at all — the difference is entirely in what you choose to do with it.
  • isDocked() returns a boolean and is called once per frame. Watch for the version that sets docked = true inside a chain of nested ifs and never sets it back to false — the bay latches green forever and never turns off.
  • Four >=/<= comparisons joined with AND. Contrast with the AABB overlap test coming in Session 12: overlap asks "do they share any space?", containment asks "is all of A inside B?". Same four edges, different question. Say that out loud — it makes Session 12 land faster.
  • Clamping before the docking test. If they test first and clamp after, the shuttle can register as docked in a position it is then moved out of. Harmless here, but it's the right habit: settle the world, then ask questions about it.

⚠️ One quirk to know before they hit it
Holding Shift and pressing a letter gives you the capital — "W", not "w" — which silently breaks WASD controls. Arrow keys are unaffected, so it won't bite in this challenge, but if a student adds WASD as a bonus it will, and it looks like magic. The fix is e.key.toLowerCase() or using e.code. It's the same trap set in the Session 10 homework.
Stretch answers

1. Score it. Inside update(), after setting docked: if it just became true and wasn't true last frame, score and move the bay. They'll need a wasDocked variable to spot the change rather than the state — a small but real idea (edge-triggered vs level-triggered), and the same one behind "why did my score go up 60 times a second?"

2. Ramp it up. bay.w -= 8; bay.h -= 6; per dock. It becomes impossible when the bay is smaller than the shuttle — worth asking them to work out the exact dock count where that happens rather than discovering it. And whether the game should stop, or clamp the size, or declare victory.

3. The stuck key. canvas.addEventListener("blur", function () { for (const k in keys) { keys[k] = false; } }); — already included in the reference above.

             shuttle.y >= bay.y &&
             shuttle.y + shuttle.h <= bay.y + bay.h;

      let speed = NORMAL_SPEED;
      if (keys["Shift"]) { speed = PRECISION_SPEED; }   // Shift is just another key

      if (keys["ArrowLeft"])  { shuttle.x -= speed; }
      if (keys["ArrowRight"]) { shuttle.x += speed; }
      if (keys["ArrowUp"])    { shuttle.y -= speed; }
      if (keys["ArrowDown"])  { shuttle.y += speed; }

      shuttle.x = Math.max(0, Math.min(W - shuttle.w, shuttle.x));
      shuttle.y = Math.max(0, Math.min(H - shuttle.h, shuttle.y));

      docked = isDocked();
    }
    // =============================================

    function draw() {
      ctx.clearRect(0, 0, W, H);

      // the bay
      if (docked === true) { ctx.strokeStyle = "#34d399"; } else { ctx.strokeStyle = "#6c8cff"; }
      ctx.lineWidth = 3;
      ctx.strokeRect(bay.x, bay.y, bay.w, bay.h);

      // the shuttle
      if (docked === true) { ctx.fillStyle = "#34d399"; } else { ctx.fillStyle = "#e9ecff"; }

      ctx.font = "15px system-ui";

        ctx.fillText("DOCKED", 12, 26);
      } else {
        ctx.fillStyle = "#a3aad6";
        ctx.fillText("Fly fully inside the bay", 12, 26);

        ctx.fillStyle = "#fbbf24";
        ctx.fillText("precision", W - 88, 26);
      }
    }

    requestAnimationFrame(loop);

🔦 Challenge 3 — Blackout · Session 11

The skill being tested: coordinate conversion, and the split between an event that records and a loop that acts. The reveal mechanic makes the pointer position matter continuously, not just at the moment of a click — so a wrong conversion is visible the whole time, not only when they miss.

The answer

    function distance(ax, ay, bx, by) {
      const dx = ax - bx;
      const dy = ay - by;
      return Math.sqrt(dx * dx + dy * dy);
    }

    // Window coordinates -> canvas coordinates. Never skip this.
    function getMousePos(event) {
      const rect = canvas.getBoundingClientRect();
      return { x: event.clientX - rect.left, y: event.clientY - rect.top };
    }

    // mousemove fires constantly, so it only RECORDS. draw() does the work.
    canvas.addEventListener("mousemove", function (event) {
      const pos = getMousePos(event);
      mouse.x = pos.x;
      mouse.y = pos.y;
    });

    canvas.addEventListener("click", function (event) {
      if (dead === true) {          // a click after ZAP just restarts
        resetGame();
        return;
      }
      const pos = getMousePos(event);
      for (let i = 0; i < items.length; i++) {
        const item = items[i];
        if (item.found === false) {
          if (distance(pos.x, pos.y, item.x, item.y) < item.r) {   // point in circle
            if (item.bad === true) {
              dead = true;                     // touched a live wire
            } else {
              item.found = true;
              score++;
            }
          }
        }
      }
    });

    function resetGame() {
      score = 0;
      dead = false;
      for (let i = 0; i < items.length; i++) { items[i].found = false; }
    }

Why each line is there

  • mousemove only writes two numbers. It fires dozens of times a second; the drawing happens in draw(). This is the keys-object pattern from Session 10 wearing a different hat, and it's worth naming the resemblance explicitly.
  • distance() is called for two different jobs. In draw() it decides visibility (is the item within the beam?). In the click handler it decides a hit (is the pointer on the item?). Different radius, different question, same function. If they only notice one thing today, make it this.
  • The dead check comes first in the click handler. An early return, same guard idea as everywhere else. Without it, the restarting click also lands on whatever is underneath and can immediately re-kill them.
  • if (item.found === false) wrapping the hit test. Stops a found fuse scoring twice. Cheap, and it teaches that "already handled" is a state worth storing.
  • resetGame() loops the array to clear every flag. Watch for the student who resets score and dead but forgets the items — the game restarts with the fuses already green.

🎯 If a student adds a "is it lit?" check to the click handler
Some will guard the click with "and it must be inside the torch beam". It's harmless — but it can never be false, because the torch is centred on the pointer, so anything you can click on is already lit. That's a lovely thing to notice: ask them to try and construct a case where it matters. A student who works out that it's redundant has genuinely understood the geometry. It would matter if the torch lagged behind the pointer or was controlled separately — which is a great stretch idea if they're flying.
Stretch answers

1. Shrink the beam. TORCH is a const, so nothing can change it — that's the real question behind the task. It has to become let, then something has to count time, which means adding a frame counter and an update() the file currently doesn't have. Good structural work in five lines.

2. Hot and cold. Loop every unfound good item, keep the smallest distance in a variable that starts huge (let best = 99999;), then choose a colour by comparing it to a few thresholds. The "start it at a huge number and shrink it" pattern is worth naming — it's how you find the minimum of anything.

3. Random every time. Same rejection-sampling idea as the big project: pick a spot, check it against everything already placed, try again if it's too close. Needs a nested loop; a solid stretch for a strong student.

4. Phone support. pointerdown works for mouse, touch and pen. But the whole game leans on hovering to sweep the torch, and a finger only exists while it's touching the glass — so on a phone the torch would only move while dragging. The honest answer is that this design needs rethinking for touch (drag to sweep, tap-and-release to grab). That's a real design conversation, not a code fix, and it's the best possible answer to give.

  <script>
    const canvas = document.getElementById("game");
    const ctx = canvas.getContext("2d");
    const W = canvas.width, H = canvas.height;

    const TORCH = 65;                  // how far the torch beam reaches
    const mouse = { x: W / 2, y: H / 2 };
    let score = 0;
    let dead = false;

    // 3 fuses to find, 2 live wires to avoid. bad:true means DON'T touch.
    const items = [
      { x: 70,  y: 70,  r: 14, bad: false, found: false },
      { x: 330, y: 105, r: 14, bad: false, found: false },
      { x: 180, y: 210, r: 14, bad: false, found: false },
      { x: 250, y: 60,  r: 14, bad: true,  found: false },
      { x: 100, y: 190, r: 14, bad: true,  found: false }
    ];

    // ================= THE ANSWER =================
    function distance(ax, ay, bx, by) {
      const dx = ax - bx;
      const dy = ay - by;
      return Math.sqrt(dx * dx + dy * dy);
    }

    // Window coordinates -> canvas coordinates. Never skip this.
    function getMousePos(event) {
      const rect = canvas.getBoundingClientRect();
      return { x: event.clientX - rect.left, y: event.clientY - rect.top };
    }

    // mousemove fires constantly, so it only RECORDS. draw() does the work.
    canvas.addEventListener("mousemove", function (event) {
      const pos = getMousePos(event);
      mouse.x = pos.x;
      mouse.y = pos.y;
    });

    canvas.addEventListener("click", function (event) {
      if (dead === true) {          // a click after ZAP just restarts
        resetGame();
        return;
      }
      const pos = getMousePos(event);
      for (let i = 0; i < items.length; i++) {
        const item = items[i];
        if (item.found === false) {
          if (distance(pos.x, pos.y, item.x, item.y) < item.r) {   // point in circle
            if (item.bad === true) {
              dead = true;                     // touched a live wire
            } else {
              item.found = true;
              score++;
            }
          }
        }
      }
    });

    function resetGame() {
      score = 0;
      dead = false;
      for (let i = 0; i < items.length; i++) { items[i].found = false; }
    }
    // =============================================

    function draw() {
      ctx.clearRect(0, 0, W, H);

      // the torch beam
      ctx.fillStyle = "rgba(108,140,255,0.13)";
      ctx.beginPath();
      ctx.arc(mouse.x, mouse.y, TORCH, 0, Math.PI * 2);
      ctx.fill();

      // an item is only drawn if the torch reaches it — or if it's already found
      for (let i = 0; i < items.length; i++) {
        const item = items[i];
        const lit = distance(mouse.x, mouse.y, item.x, item.y) < TORCH;
        if (item.found === true || lit === true) {
          if (item.found === true)   { ctx.fillStyle = "#34d399"; }
          else if (item.bad === true) { ctx.fillStyle = "#fb7185"; }
          else                        { ctx.fillStyle = "#fbbf24"; }
          ctx.beginPath();
          ctx.arc(item.x, item.y, item.r, 0, Math.PI * 2);
          ctx.fill();
        }
      }

      ctx.fillStyle = "#e9ecff";
      ctx.font = "15px system-ui";
      ctx.fillText("Fuses: " + score + " / 3", 12, 24);

      ctx.textAlign = "center";
      if (dead === true) {
        ctx.fillStyle = "#fb7185";
        ctx.font = "28px system-ui";
        ctx.fillText("ZAP!", W / 2, H / 2 - 6);
        ctx.fillStyle = "#a3aad6";
        ctx.font = "14px system-ui";
        ctx.fillText("click anywhere to try again", W / 2, H / 2 + 20);
      } else if (score === 3) {
        ctx.fillStyle = "#34d399";
        ctx.font = "24px system-ui";
        ctx.fillText("POWER RESTORED", W / 2, H / 2);
      }
      ctx.textAlign = "left";
    }

    function loop() { draw(); requestAnimationFrame(loop); }
    requestAnimationFrame(loop);
  </script>
